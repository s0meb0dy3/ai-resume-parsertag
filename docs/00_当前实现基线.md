## 文件与解析能力

同步和异步公开文件白名单均为 PDF、DOCX、JPG、JPEG、PNG，并校验扩展名、真实
内容、类型一致性和资源预算。

同步文件链：

```text
URL / 本地路径 / Base64
-> PDF: pymupdf4llm 与 PyMuPDF 文本择优
-> DOCX: OOXML 安全检查后由 Mammoth 抽取文本
-> 有效文本: 单次文本 LLM 生成完整 Resume
-> 无文本或汉字数量不少于 100 且信息熵低于 3.0 / 图片型文档: 视觉 LLM
-> JSON repair、后处理、ResumeData 归一
```

异步文件链：

```text
上传或 URL PDF / DOCX / JPG / JPEG / PNG
-> PDF 直接渲染页面
-> DOCX 经 Mammoth HTML + PyMuPDF Story 排版为 A4 页面
-> JPEG / PNG 由 Pillow 安全解码
-> 页面图片不超过 8 张时单次视觉 LLM，超过 8 张时分批并发
-> 批次合并、后处理、ResumeData 归一
```

异步链不调用 Python 文本抽取器。DOCX 中 Mammoth 只用于本地页面排版，送入模型
的内容始终为图片。同步和异步因此可能产生不同解析结果。

## Resume 与标签契约

公开 Resume 固定包含：

```text
candidate
educations[]
works[]
projects[]
```

公开 Schema 不增加 `employmentType`。当前任职常见写法归一为“至今”；实习和
兼职通过职位及描述关键词识别，不计入正式工作年限、稳定性和时间线重叠。

正向维度固定为教育背景、公司背景、工作年限、技能标签、行业背景。公共打标结果
必须返回：

- 顶层 `mappingVersion`。
- 维度 `dimensionId/dimension/displayName`。
- 标签 `tagId/tag/source`。
- `source` 仅允许 `rule/llm/hybrid`。

标签 ID 映射唯一事实源为 `schemas/tag_value_id_mapping.json`。后端应以
`mappingVersion + dimensionId + tagId` 作为稳定关联键，同时保存文本快照；不得用
数组位置或展示文案作为数据库主关联键。

## 日志基线

文本日志格式为：

```text
YYYY-MM-DD HH:mm:ss | LEVEL | [中文业务类型] [文件名] | [文件.py:行号 方法名] | 消息
```

- 不显示 `trace/task` 文本前缀。
- 除 `/health`、`/openapi.json` 外，JSON 接口先输出完成信息 JSON，再输出完整响应 JSON。
- 异步轮询处理中状态为 DEBUG，终态为 INFO。
- 非零业务码和 HTTP 4xx 为 WARNING，HTTP 5xx 为 ERROR。
- 控制台日期为蓝色，DEBUG/INFO/WARNING/ERROR 分别为青/绿/黄/红色；文件日志无 ANSI 颜色。
- 完整响应含 PII，生产必须使用受控日志域、访问审计和保留期限。

## 当前运行边界

- 异步任务保存在单进程内存中，默认 TTL 120 分钟并从创建时间计算。
- 服务重启、进程切换或多副本路由可能导致任务无法轮询。
- URL 输入缺少完整 SSRF 防护；`type=file` 缺少可信根目录约束。
- 多页面视觉解析单批失败可能被空结果合并，尚无 `partial_success` 和失败页码。
- `/health` 只代表进程存活，不代表模型服务就绪。
