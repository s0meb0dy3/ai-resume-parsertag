## 1. 适用范围

本文用于克隆项目后的接口冒烟和集成测试，与 [04_测试用例.md](04_测试用例.md)
互补。接口字段以 FastAPI/Pydantic 和 [openapi.json](openapi.json) 为准。

包含：

- 基础状态、模型列表、标签配置和映射查询。
- 同步仅解析、仅打标、解析加打标。
- 异步上传、URL 批量、仅解析、仅打标、混合提交、轮询和任务列表。
- Langfuse trace 抽查。

不包含：

- `POST /v1/chat/completions`。
- 会修改运行时配置的标签写接口。
- 内部算法调试接口。

## 2. 测试准备

### 2.1 前置条件

1. 按 [05_运维部署手册.md](05_运维部署手册.md) 启动服务。
2. 准备一份有权使用的 PDF 测试简历。
3. 确认服务端能访问 URL 测试文件。
4. 异步任务使用单进程、单副本部署。
5. 测试响应可能包含 PII，测试结束后及时清理。

### 2.2 环境变量

按实际环境修改：

```bash
# 本地常见地址；远程环境填写实际服务地址。
export BASE_URL="http://localhost:21804"

# 必须替换为当前机器上可读取的 PDF 绝对路径。
export TEST_PDF="/absolute/path/to/test-resume.pdf"

# 服务端可访问的 URL。默认文件只用于验证 URL 下载链路，不用于质量评测。
export TEST_URL="https://www.w3.org/WAI/ER/tests/xhtml/testfiles/resources/pdf/dummy.pdf"
export TEST_URL_NAME="remote-test.pdf"

# 可选岗位上下文。
export JOB_TITLE=""
export REQUIRED_SKILLS=""

test -r "$TEST_PDF" || {
  echo "TEST_PDF 不存在或不可读: $TEST_PDF" >&2
  exit 1
}
```

## 4. 通用检查项

### 4.1 成功判断

- 同时检查 HTTP 状态码和业务 `code`。
- 同步批量接口检查 `success/failed` 和 `results[].code`。
- 异步提交接口检查 `submitted/failed` 和 `tasks[].code`。
- 异步任务只有 `status=3` 表示成功，`status=4` 表示失败。

### 4.2 Resume 契约

公开 Resume 固定包含：

```text
candidate
educations[]
works[]
projects[]
```

`works[]` 只包含：

```text
company/position/description/startDate/endDate
```

### 4.3 标签契约

完整结果应包含：

- 顶层 `mappingVersion`。
- 维度 `dimensionId/dimension/displayName`。
- 标签值 `tagId/tag/source`。
- `source` 只允许 `rule/llm/hybrid`。

标签位置：

```text
result.positiveTags.tagsArray
result.negativeTags.tagsArray
```

## 5. 基础与标签查询

### 5.1 健康检查

```bash
curl -fsS "$BASE_URL/health" | python3 -m json.tool
```

预期：HTTP 200，`status=healthy`。该接口不检查模型服务。

### 5.2 模型列表

```bash
curl -fsS "$BASE_URL/v1/models" | python3 -m json.tool
```

预期：HTTP 200，返回逻辑模型列表。

### 5.3 标签配置

```bash
curl -fsS "$BASE_URL/api/tags/config" | python3 -c '
import json, sys
x = json.load(sys.stdin)["data"]
print("mappingVersion:", x["mappingVersion"])
print("positive/negative:", len(x["positiveDimensions"]), len(x["negativeDimensions"]))
'
```

预期：正向维度 5 个、负向维度 4 个。

### 5.4 标签映射

```bash
curl -fsS "$BASE_URL/api/tags/mapping" | python3 -c '
import json, sys
x = json.load(sys.stdin)["data"]
print("mappingVersion:", x["mappingVersion"])
print("dimensions/mappings:", len(x["dimensions"]), len(x["mappings"]))
'
```

预期：维度总数为 9，`mappingVersion` 与标签配置接口一致。映射数量以当前版本为准，
调用方不要写死。

## 6. 同步接口

### 6.1 同步仅解析

生成 Base64 请求：

```bash
python3 - "$TEST_PDF" <<'PY'
import base64, json, os, sys

path = sys.argv[1]
with open(path, "rb") as f:
    content = base64.b64encode(f.read()).decode()

payload = {
    "resumes": [{
        "type": "base64",
        "file": {"name": os.path.basename(path), "content": content}
    }],
    "max_concurrency": 1
}
json.dump(payload, open("/tmp/sync-parse-request.json", "w"))
PY

curl -fsS -X POST "$BASE_URL/api/resume/sync/parse" \
  -H 'Content-Type: application/json' \
  --data-binary @/tmp/sync-parse-request.json \
  -o /tmp/sync-parse-response.json

python3 - <<'PY'
import json
x = json.load(open("/tmp/sync-parse-response.json"))
r = x["results"][0]["data"]["resume"]
print("total/success/failed:", x["total"], x["success"], x["failed"])
print("educations/works/projects:", len(r["educations"]), len(r["works"]), len(r["projects"]))
PY
```

预期：`success=1`，Resume 结构符合第 4 节。字段准确率应与当前测试文件的人工标注
或黄金集比较，不应照搬其他简历的数量。

URL 输入必须使用 `file.path`：

```bash
curl -fsS -X POST "$BASE_URL/api/resume/sync/parse" \
  -H 'Content-Type: application/json' \
  -d "{\"resumes\":[{\"type\":\"url\",\"file\":{\"name\":\"$TEST_URL_NAME\",\"path\":\"$TEST_URL\"}}]}" \
  | python3 -m json.tool
```

### 6.2 同步仅打标

将 `sync/parse` 的 `results[0].data` 直接作为输入：

```bash
python3 - <<'PY'
import json, os

parsed = json.load(open("/tmp/sync-parse-response.json"))
payload = {
    "resumes": [parsed["results"][0]["data"]],
    "jobTitle": os.getenv("JOB_TITLE", ""),
    "requiredSkills": os.getenv("REQUIRED_SKILLS", ""),
    "max_concurrency": 1
}
json.dump(payload, open("/tmp/sync-tag-request.json", "w"), ensure_ascii=False)
PY

curl -fsS -X POST "$BASE_URL/api/resume/sync/tag" \
  -H 'Content-Type: application/json' \
  --data-binary @/tmp/sync-tag-request.json \
  | python3 -c '
import json, sys
x = json.load(sys.stdin)
r = x["results"][0]["data"]["result"]
print("success:", x["success"])
print("mappingVersion:", r["mappingVersion"])
print("positive:", [v["dimension"] for v in r["positiveTags"]["tagsArray"]])
print("negative hits:", r["negativeTags"]["hitCount"])
'
```

预期：`success=1`，标签结构和 ID 符合第 4 节。具体标签取决于简历、岗位上下文、
运行时配置和模型结果。

### 6.3 同步解析加打标

复用第 6.1 节的文件条目：

```bash
python3 - <<'PY'
import json, os

payload = json.load(open("/tmp/sync-parse-request.json"))
payload.update({
    "jobTitle": os.getenv("JOB_TITLE", ""),
    "requiredSkills": os.getenv("REQUIRED_SKILLS", "")
})
json.dump(payload, open("/tmp/sync-batch-request.json", "w"), ensure_ascii=False)
PY

curl -fsS -X POST "$BASE_URL/api/resume/sync/batch" \
  -H 'Content-Type: application/json' \
  --data-binary @/tmp/sync-batch-request.json \
  | python3 -c '
import json, sys
x = json.load(sys.stdin)
print("total/success/failed:", x["total"], x["success"], x["failed"])
print("status:", x["results"][0]["data"]["status"])
'
```

预期：`success=1`，单项 `status=3`。

## 7. 异步接口

### 7.1 轮询函数

在 Shell 中定义：

```bash
poll_task() {
  local task_id="$1"
  for i in $(seq 1 200); do
    local response status
    response=$(curl -fsS "$BASE_URL/api/resume/async/result?taskId=$task_id") || return 1
    status=$(printf '%s' "$response" | python3 -c \
      'import json,sys; print(json.load(sys.stdin).get("data",{}).get("status"))')
    echo "poll=$i status=$status"
    [ "$status" = "3" ] && return 0
    [ "$status" = "4" ] && { printf '%s\n' "$response"; return 1; }
    sleep 3
  done
  echo "poll timeout" >&2
  return 1
}
```

状态含义：

```text
0 待处理 → 1 解析中 → 2 打标中 → 3 完成 / 4 失败
```

### 7.2 异步单文件上传

```bash
TASK_ID=$(
  curl -fsS -X POST "$BASE_URL/api/resume/async/parse" \
    -F "file=@$TEST_PDF;type=application/pdf" \
    -F 'requestId=manual-async-upload-001' \
    -F "jobTitle=$JOB_TITLE" \
    -F "requiredSkills=$REQUIRED_SKILLS" \
  | python3 -c 'import json,sys; print(json.load(sys.stdin)["data"]["taskId"])'
)

poll_task "$TASK_ID"
```

multipart 字段名是 `file`。相同 `requestId` 在同一进程内应复用原任务。

### 7.3 URL 批量解析加打标

```bash
curl -fsS -X POST "$BASE_URL/api/resume/async/batch" \
  -H 'Content-Type: application/json' \
  -d "{\"resumes\":[{\"type\":\"url\",\"file\":{\"name\":\"$TEST_URL_NAME\",\"path\":\"$TEST_URL\"}}]}" \
  | tee /tmp/async-batch-submit.json \
  | python3 -m json.tool
```

预期：`submitted=1`。取 `tasks[0].taskId` 后使用 7.1 节轮询。

### 7.4 URL 批量仅解析

```bash
curl -fsS -X POST "$BASE_URL/api/resume/async/batch/parse" \
  -H 'Content-Type: application/json' \
  -d "{\"resumes\":[{\"type\":\"url\",\"file\":{\"name\":\"$TEST_URL_NAME\",\"path\":\"$TEST_URL\"}}]}" \
  | tee /tmp/async-parse-submit.json \
  | python3 -m json.tool
```

轮询成功后，`data.result` 包含 `filename/extra/resumeParseFinishTime/resume`。

### 7.5 异步仅打标

将 7.4 节的终态响应保存为 `/tmp/async-parse-result.json`：

```bash
python3 - <<'PY'
import json, os

parsed = json.load(open("/tmp/async-parse-result.json"))
payload = {
    "resumes": [parsed["data"]["result"]],
    "jobTitle": os.getenv("JOB_TITLE", ""),
    "requiredSkills": os.getenv("REQUIRED_SKILLS", "")
}
json.dump(payload, open("/tmp/async-tag-request.json", "w"), ensure_ascii=False)
PY

curl -fsS -X POST "$BASE_URL/api/resume/async/batch/tag" \
  -H 'Content-Type: application/json' \
  --data-binary @/tmp/async-tag-request.json \
  | tee /tmp/async-tag-submit.json \
  | python3 -m json.tool
```

预期：任务成功入队，且不重新解析原文件。

### 7.6 异步混合提交

```bash
curl -fsS -X POST "$BASE_URL/api/resume/async/batch/multiform" \
  -F "files=@$TEST_PDF;type=application/pdf" \
  -F "resumes=[{\"type\":\"url\",\"file\":{\"name\":\"$TEST_URL_NAME\",\"path\":\"$TEST_URL\"}}]" \
  -F "jobTitle=$JOB_TITLE" \
  -F "requiredSkills=$REQUIRED_SKILLS" \
  | python3 -m json.tool
```

预期：`total=2`，上传项和 URL 项分别返回任务结果。该接口的上传字段名是 `files`。

### 7.7 结果与任务列表

查询单个任务：

```bash
curl -fsS "$BASE_URL/api/resume/async/result?taskId=$TASK_ID" | python3 -m json.tool
```

查询已完成任务：

```bash
curl -fsS "$BASE_URL/api/tasks?status=3&include_result=false" | python3 -c '
import json, sys
x = json.load(sys.stdin)["data"]
print("total:", x["total"])
print("returned:", len(x["tasks"]))
'
```

注意：

- 不存在或已过期任务返回 HTTP 200、业务 `code=2001`。
- 任务只保存在当前进程内存，重启或 TTL 到期后丢失。
- `include_result=true` 会返回完整简历，可能包含 PII。

## 8. Langfuse 验证

公司内网 Langfuse 地址：

```bash
export LANGFUSE_BASE_URL="http://10.2.5.117:3000"
```

从本地 `.env` 读取密钥：

```bash
PK=$(grep '^LANGFUSE_PUBLIC_KEY=' .env | cut -d= -f2-)
SK=$(grep '^LANGFUSE_SECRET_KEY=' .env | cut -d= -f2-)
AUTH=$(printf '%s' "$PK:$SK" | base64 -w0)
```

按接口路径查询最新 trace：

```bash
TRACE_NAME='/api/resume/sync/parse'
ENCODED_NAME=$(python3 -c \
  'import sys,urllib.parse; print(urllib.parse.quote(sys.argv[1], safe=""))' \
  "$TRACE_NAME")

curl -fsS \
  "${LANGFUSE_BASE_URL}/api/public/traces?name=$ENCODED_NAME&limit=3" \
  -H "Authorization: Basic $AUTH" \
  | python3 -m json.tool
```

检查：

1. trace 名与接口路径一致。
2. 关键 span 存在预期 input/output。
3. 图片只显示 `[image:redacted]`，不包含 Base64。
4. trace 可能包含简历 PII，必须限制访问和保留周期。

未配置 Langfuse 时可跳过本节，不影响业务接口测试。

## 9. 常见问题

| 问题 | 正确处理 |
| ---- | ---- |
| URL 条目使用 `file.url` | 必须使用 `file.path` |
| `async/batch` 传 Base64 或本地文件 | 该接口只支持 `type=url` |
| `async/parse` 使用字段 `files` | 单文件接口使用 `file` |
| `async/batch/multiform` 使用字段 `file` | 混合批量接口使用 `files` |
| `async/batch/parse` 请求体使用 `items` | 正确字段为 `resumes` |
| 在 `tagInfo` 下查找最终标签 | 标签位于 `positiveTags/negativeTags` |
| `submitted=0` 就判断模型故障 | 先检查 URL、DNS、证书、超时和文件类型 |
| 在 `status=0/1/2` 时读取结果 | 只有 `status=3` 才读取 `data.result` |
| 把 `/api/tasks.data` 当作数组 | 数组位于 `data.tasks`，数量位于 `data.total` |
| 重启后查询不到任务 | 当前任务存储在进程内存中，属于已知限制 |
