## 1. 测试分层

| 层级 | 目标 | 当前状态 |
|---|---|---|
| 单元/组件测试 | 文本抽取、契约、Prompt、规则、映射、日志、模型回退 | 已有 pytest 自动化 |
| API 路由测试 | HTTP、Pydantic、鉴权、状态码和响应 | 缺少完整 `TestClient` 覆盖 |
| 集成测试 | 真实模型、MinIO、真实文档和图片 | 有手工脚本，依赖外部环境 |
| 安全测试 | SSRF、本地路径、压缩包、鉴权、PII | DOCX 安全边界有组件测试，其余不足 |
| 性能测试 | 并发、多页面视觉文档、内存、模型压力 | 有异步压力脚本，缺少正式报告和门槛 |

优先级：P0 为上线阻断，P1 为重要回归，P2 为兼容或专项验证。

## 2. 自动化测试基线

执行：

```bash
pytest -q
```

当前自动化覆盖：

| 文件 | 主要覆盖 |
|---|---|
| `test/test_document_text.py` | PDF/DOCX/图片类型、安全预算、抽取器比较和关键字段缺失 |
| `test/test_sync_resume_parser.py` | 同步单次 LLM、扫描 PDF 和图片型 DOCX 视觉降级 |
| `test/test_openapi_contract.py` | OpenAPI 快照、唯一 operationId、非空响应 Schema 和错误状态声明 |
| `test/test_resume_contract.py` | Resume 数组空值归一和非法类型拒绝 |
| `test/test_prompt_modules.py` | Prompt 模块边界、允许值说明、技能歧义和负向证据要求 |
| `test/test_tag_mapping_and_config.py` | 标签 ID 一一映射、技能库一致性、结构锁定、公共响应兼容 |
| `test/test_work_experience.py` | 年限分段、重叠区间、实习、空窗和时间精度 |
| `test/test_positive_tag_order.py` | 正向维度顺序、展示名、技能上限和日志 |
| `test/test_model_fallback.py` | 模型候选顺序、思考参数兼容和回退 |
| `test/test_logging_and_polling.py` | 文件名规范化、操作边界、终态耗时、异步多格式白名单与来源校验 |
| `test/test_tagging.py` | 正向/负向标签基础逻辑 |
| `test/test_reference_data.py` | 院校完整性、公司多资质、行业强证据、技能否定语境 |
| `test/test_golden_evaluator.py` | 黄金集契约、PII 防护、文件摘要、指标和阈值 |

仍属于集成/手工验证，不能由单元测试通过替代。

## 3. 功能验收用例

### 3.1 基础和契约

| 编号 | 用例 | 操作 | 预期 | 优先级 |
|---|---|---|---|:---:|
| TC-001 | 存活探针 | `GET /health` | HTTP 200，`status=healthy` | P0 |
| TC-002 | OpenAPI | 访问 `/openapi.json` | 路径与代码一致，所有 JSON 200 响应具有非空 Schema | P1 |

| TC-005 | Resume 非法集合 | `works` 为字符串 | 校验失败，不进入打标 | P0 |

| 编号 | 用例 | 操作 | 预期 | 优先级 |

| TC-105 | 有效 DOCX | 提交包含段落/表格文本的 DOCX | Mammoth 抽取并结构化 | P0 |
| TC-106 | 图片型 DOCX | 提交无文本但正文引用多张图片的 DOCX | 按正文顺序提取图片并视觉解析 | P0 |

## 4. API 与安全专项

这些用例当前缺少自动化覆盖，应在上线前补齐：

| 编号 | 用例 | 预期 | 优先级 |
|---|---|---|:---:|
| SEC-001 | URL 指向 localhost、云元数据和内网 IP | SSRF 防护拒绝；当前实现预计不能通过 | P0 |
| SEC-002 | `type=file` 读取上传目录外路径 | 根目录限制拒绝；当前实现预计不能通过 | P0 |
| SEC-003 | 未认证查询 `/api/tasks?include_result=true` | 应拒绝；当前实现预计不能通过 | P0 |
| SEC-004 | 非白名单 Origin 携带凭证 | CORS 应拒绝；当前实现预计不能通过 | P0 |
| SEC-005 | 超大上传与超大下载 | 在读入全部内存前拒绝 | P0 |
| SEC-006 | 日志 PII | 完整 JSON 日志仅进入授权日志域，具备访问控制、保留期限和删除审计，不流入公共日志平台 | P0 |
| SEC-007 | Prompt 注入简历 | 输出仍受 Schema 和允许值约束 | P1 |

## 5. 性能与稳定性

| 编号 | 场景 | 建议观测指标 |
|---|---|---|
| PERF-001 | 1/5/10/20 并发文本 PDF | 吞吐、P50/P95、模型错误率 |
| PERF-002 | 20 页扫描 PDF | 峰值 RSS、渲染耗时、部分失败页 |
| PERF-003 | 同步批量 50 份 | 请求耗时、线程数、模型并发 |
| PERF-004 | 队列持续超过处理能力 | 任务数、内存、拒绝/背压行为 |
| PERF-005 | 模型主实例故障 | 回退成功率和额外耗时 |

当前实现没有有界提交队列和全局模型服务速率限制，压测必须在隔离环境进行。

## 6. 手工集成脚本

以下文件依赖真实文件、MinIO 或模型服务，不应当作离线 pytest 成功基线：

- `test/stress_test_async.py`
- `test/upload_resume.py`
- `test/test_minio_url.py`

执行前设置测试专用模型凭据，不得在输出或报告中保留真实候选人 PII。

真实简历黄金集使用 `evaluation/private/` 或外部受控目录，不属于公开测试夹具。
通过 `scripts/evaluate_golden_set.py` 校验匿名文件名、SHA-256、清单隐私和发布阈值。

## 7. 发布门槛

1. `pytest -q` 全部通过，不新增未解释 warning。
2. 所有 P0 功能用例通过。
3. SEC-001~SEC-006 在生产入口或应用层有明确实现并通过验证。
4. 使用固定真实简历黄金集完成解析质量回归，`fieldAccuracy`、
   `positiveMicroF1`、`negativeF1` 全部达到私有清单阈值且不得低于上一版本；同一
   发布候选至少重复 3 次并以最差一次判断，禁止只选取通过结果。
5. 在目标容器资源下完成性能测试，无 OOM、任务静默丢失或模型服务过载。
6. OpenAPI、接口文档、Postman 示例和代码路由一致。
