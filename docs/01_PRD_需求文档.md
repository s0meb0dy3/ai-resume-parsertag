## 1. 背景与目标

招聘系统接收的简历主要为 PDF，也包含 DOCX。人工阅读难以稳定沉淀候选人基础信息、教育经历、工作经历、项目经历、技能和风险提示。本项目将简历转换为统一 JSON，并结合岗位上下文生成正向标签和负向风险标签。

核心目标：

1. 尽可能完整地提取 PDF、DOCX、JPEG、PNG 中的可见信息并结构化。
2. 输出稳定、可校验的候选人、教育、工作和项目数据契约。
3. 基于固定标签体系输出可解释的正向标签和风险提示。
4. 提供同步、异步、批量、仅解析和仅打标能力。
5. 支持模型回退、运行日志、结果落盘和可选 Langfuse 追踪。

标签仅作为招聘人员的辅助信息，不应作为自动淘汰或录用的唯一依据。

## 2. 用户与场景

| 角色 | 主要场景 |
|---|---|
| HR 系统/招聘官网 | 提交简历、轮询任务、保存结构化结果和标签 |
| 后端调用方 | 通过同步或异步 API 集成解析能力 |

| 运维人员 | 部署服务、配置模型、查看日志和处理故障 |

## 3. 功能需求

### 3.1 文档输入

| 能力 | 当前实现 |
|---|---|
| 单文件异步上传 | 支持真实 PDF/DOCX/JPG/JPEG/PNG，固定视觉解析，大小由 `MAX_FILE_SIZE_MB` 控制 |
| 异步 URL 批量 | 支持 `type=url` 的 PDF/DOCX/JPG/JPEG/PNG，单次 1~20 份 |
| 异步混合批量 | 上传与 URL 多格式简历可混合，合计最多 20 份 |
| 同步批量 | 支持 PDF、DOCX、JPG、JPEG、PNG；来源支持 URL、服务器文件路径、Base64 |
| OpenAI 兼容入口 | 同步和 `async_mode=true` 均支持 PDF/DOCX/JPG/JPEG/PNG |
| 已解析 JSON | 仅打标接口接收统一 Resume 数据契约 |

旧版 `.doc`、GIF/TIFF/WebP 等其他图片以及扩展名与真实内容不一致的文件不属于当前
有效输入。同步与异步公开后缀白名单均为 PDF、DOCX、JPG、JPEG、PNG。

### 3.2 简历解析

系统应：

- 识别真实文件内容，拒绝扩展名伪装、损坏或加密文档。
- 对文本 PDF 比较 `pymupdf4llm` Markdown 与 PyMuPDF 原生文本，选择更完整结果。
- 对无文本层的扫描 PDF 降级到视觉解析。
- 对 DOCX 在 Mammoth 抽取前执行 ZIP/OOXML 条目数、路径、解压大小和压缩比检查。
- DOCX 没有可读文本但正文包含简历扫描图片时，按正文关系顺序提取图片并执行
  视觉解析；没有有效图片或超过视觉预算时明确失败。
- 将 LLM 输出修复、校验并归一为 Resume Pydantic 契约。
- 保留姓名、联系方式、教育、工作、项目和自我评价等可见信息，不从缺失内容推断事实。

同步文本解析单次最多处理 `SYNC_DOCUMENT_MAX_TEXT_CHARS` 个字符；超过上限直接失败，不拆分为多个文本模型请求。

### 3.3 智能打标

正向标签固定为五个维度：

| dimension | 展示名 | 主要来源 |
|---|---|---|
| `education` | 教育背景 | 确定性学校/学历规则 |
| `companyBg` | 公司背景 | LLM 召回 + 公司资质库/明确文本复核 |
| `workYears` | 工作年限 | 工作时间线确定性计算 |
| `skills` | 技能标签 | LLM 筛选 + 原文证据 + 本地技能库复核/补齐 |
| `industry` | 行业背景 | LLM 召回 + 强关键词/排除语境复核 |

要求：

- 所有输出值必须属于当前运行时 `allowedValues`。
- 技能标签需有简历证据，别名存在歧义时不得任意映射。
- 技能标签最多输出 12 个。
- 公共打标响应同时返回 `mappingVersion`、维度 `dimensionId`、标签 `tagId` 和业务文本 `tag`；后端保存前必须校验映射版本。
- `source` 只允许 `rule`、`llm`、`hybrid`；教育、工作年限和内置负向标签为 `rule`。
- 工作年限采用“应届、往届无经验、1年以下、1-3年（满1年）、3-5年（满3年）、5-10年（满5年）、10年及以上”，数值档位为左闭右开。
- 实习和兼职不计入正式年限，也不参与职业稳定性和时间线重叠规则。
- 负向风险必须包含命中证据、严重等级和扣分，不得只输出抽象结论。

### 3.4 同步与异步

| 方式 | 行为 | 适用场景 |
|---|---|---|
| 异步 | 立即返回 `taskId`，客户端轮询状态 | 在线业务、批量提交、耗时任务 |
| 同步 | 当前请求等待所有项完成并返回结果 | 调试、脚本、离线处理 |
| 仅解析 | 输出可复用的 Resume JSON | 一次解析、多岗位打标 |
| 仅打标 | 对已解析 Resume 生成标签 | 多岗位重复评估 |

异步状态为 `0` 待处理、`1` 解析中、`2` 打标中、`3` 完成、`4` 失败。

### 3.5 标签配置

当前产品约束是标签结构锁定：

- 可以查询全部配置。
- 可以修改既有正向维度的展示名、启用状态和允许值。
- 可以修改既有负向维度的展示名和启用状态。
- 可以修改既有负向规则的已有字段。
- 可以修改风险扣分并重置默认配置。
- 不允许新增/删除维度，不允许新增/删除规则；相关兼容路由固定返回 HTTP 409。

生产环境应设置 `TAGS_ADMIN_TOKEN`。未设置时所有标签配置写接口跳过鉴权，只适用于可信隔离环境。

## 4. 输出要求

完整解析加打标结果包含：

- `taskId`、解析和打标完成时间。
- `candidate` 候选人基础信息。
- `educations`、`works`、`projects` 数组。
- `positiveTags.tagsArray`，维度顺序固定。
- `negativeTags.hitCount`、`deductionScore`、`tagsArray`。

公共输出不得包含内部技能证据文本、Prompt 或模型思考内容。标签 ID 属于当前公开
契约，必须同时返回 `mappingVersion/dimensionId/tagId`。

## 5. 非功能需求

| 维度 | 要求与现状 |
|---|---|
| 完整性 | 同步链对 PDF 双抽取器比较并提供视觉降级；异步链将五种支持格式统一转换为图片解析 |
| 稳定性 | 模型调用支持备用模型回退和有限重试 |
| 性能 | 全局线程池默认 24；同步批量并发请求值限制为 1~30 |
| 可观测性 | 结构化日志、请求上下文、结果文件、可选 Langfuse |
| 配置安全 | 必填模型地址/API Key 通过环境变量注入 |
| 隐私 | 简历、日志和结果均含 PII，生产必须限制访问并设置清理周期 |
| 部署 | 支持本地、Docker Compose、离线镜像和现有 Kubernetes CI |

## 6. 验收标准

### 6.1 功能验收

1. 有文本层的 PDF、文本 DOCX 和图片型 DOCX 能通过同步接口返回结构化 Resume。
2. 扫描 PDF 能从同步入口正确降级到视觉解析。
3. PDF、DOCX、JPG、JPEG、PNG 均能通过异步文件入口完成解析；送入异步模型的内容只包含页面图片，不包含 Python 抽取文本。
4. 异步任务能经历合法状态并在终态返回结果或错误。
5. 批量处理中单项失败不阻断其他项。
6. 仅解析结果可以直接作为仅打标输入。
7. 标签值、顺序、技能数量和风险扣分符合运行时配置。
8. 标签结构变更路由返回 HTTP 409，允许的更新可原子生效。

### 6.2 质量验收

- 仓库自动化测试全部通过。
- 使用真实文本 PDF、扫描 PDF、DOCX、JPEG/PNG、损坏文件和扩展名伪装文件完成回归。
- 对核心字段建立人工标注集，至少统计姓名、电话、邮箱、学校、公司、岗位和时间字段准确率。
- 在目标部署规格下完成并发和长文档内存压测。

## 7. 当前边界与风险

- 异步任务存储在单进程内存中，重启后丢失，不支持多副本一致轮询。
- TTL 从任务创建时间计算，运行时间过长的任务也可能被清理。
- URL 下载、本地路径输入、未鉴权任务查询和宽松 CORS 需要在生产入口层额外防护。
- 完整简历结果会写入日志和 `results/`，必须建立 PII 脱敏与删除策略。
- 当前 `/health` 只表示进程存活，不验证模型、存储和配置就绪。
- 标签与风险识别存在模型误判可能，必须保留人工复核。

## 8. 非本期范围

- OCR 引擎训练、招聘决策自动化和候选人排序。
- 任务状态跨实例持久化和消息队列调度。
- 旧版 `.doc`、加密 PDF 及 JPEG/PNG 之外图片格式的解析。
- 在公开 Resume 中增加 `employmentType` 等任职类型字段；当前通过职位和描述兼容识别。
