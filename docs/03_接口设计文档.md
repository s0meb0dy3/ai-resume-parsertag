## 1. 公共约定

### 1.1 服务地址与请求类型

```text
http://<host>:21804
```

支持的请求类型：

- JSON：批量异步、同步、仅打标和 OpenAI 兼容接口。
- `multipart/form-data`：单文件异步上传、混合批量。
- Query：任务结果和任务列表。

### 1.2 认证现状

- 简历解析、任务查询、模型列表、标签配置查询和算法调试接口当前没有内建认证。
- 标签配置写接口仅在设置 `TAGS_ADMIN_TOKEN` 后校验 `Authorization: Bearer <token>`。
- 未设置 `TAGS_ADMIN_TOKEN` 时，标签写接口跳过认证。

生产环境必须通过应用改造或 API 网关补充统一认证、任务所有权和租户隔离。

### 1.3 文件能力矩阵

| 入口 | PDF | DOCX | JPEG/PNG | 来源 | 数量 |
|---|:---:|:---:|:---:|---|---:|
| `/api/resume/async/parse` | 是 | 是 | 是 | 直接上传 | 1 |
| `/api/resume/async/batch` | 是 | 是 | 是 | URL | 1~20 |
| `/api/resume/async/batch/parse` | 是 | 是 | 是 | URL | 1~20 |
| `/api/resume/async/batch/multiform` | 是 | 是 | 是 | 上传 + URL | 1~20 |
| `/api/resume/sync/batch` | 是 | 是 | 是 | URL / file / base64 | 1~50 |
| `/api/resume/sync/parse` | 是 | 是 | 是 | URL / file / base64 | 1~50 |
| `/v1/chat/completions` 同步 | 是 | 是 | 是 | URL / file / base64 | 单份或批量 |
| `/v1/chat/completions` 异步 | 是 | 是 | 是 | URL / file / base64 | 仅单份 |

文件必须通过真实内容检测。异步解析支持 PDF/DOCX/JPEG/PNG，并统一转换为图片后
执行视觉解析：DOCX 由 Mammoth+PyMuPDF 排版渲染，无正文页面时回退到内嵌图片；
独立 JPEG/PNG 通过像素预算后直接进入视觉模型。

### 1.4 岗位上下文

以下字段均可选，仅解析接口会忽略其打标语义：

| 字段 | 类型 | 说明 |
|---|---|---|
| `jobTitle` | string | 目标岗位名称 |
| `requiredSkills` | string | 岗位技能，通常逗号分隔 |
| `jobDescription` | string | JD 全文 |
| `jobSensitiveWords` | string | 请求级附加风险关键词；地域规则默认预设“广西” |

### 1.5 异步任务状态

| status | 含义 | 终态 |
|:---:|---|:---:|
| `0` | 待处理 | 否 |
| `1` | 简历解析中 | 否 |
| `2` | 标签打标中 | 否 |
| `3` | 任务完成，读取 `data.result` | 是 |
| `4` | 任务失败，读取 `data.errorMsg` | 是 |

任务默认保留 120 分钟，由 `TASK_TTL_MINUTES` 控制，并按创建时间计算。轮询
接口的过期提示读取同一配置值，运行时文案与 Swagger 描述保持一致。

## 3. 异步接口

### 3.1 单文件上传

```http
POST /api/resume/async/parse
Content-Type: multipart/form-data
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|:---:|---|
| `file` | File | 是 | 内容有效且扩展名与真实类型一致的 PDF/DOCX/JPG/JPEG/PNG |
| `requestId` | string | 否 | 当前进程内幂等标识 |
| 岗位上下文字段 | string | 否 | 见 2.4 |

```bash
curl -X POST "$BASE_URL/api/resume/async/parse" \
  -F 'file=@resume.pdf' \
  -F 'requestId=delivery-001' \
  -F 'jobTitle=后端工程师'
```

成功响应：

```json
{
  "code": 0,
  "msg": "success",
  "data": {
    "taskId": "uuid",
    "status": 0,
    "estimatedSeconds": 90
  }
}
```

同一 `requestId` 会线性扫描当前进程内任务并复用已有任务；重启、TTL 清理或请求落到其他副本后不再具备幂等效果。

### 3.2 URL 批量解析加打标

```http
POST /api/resume/async/batch
Content-Type: application/json
```

```json
{
  "jobTitle": "后端工程师",
  "requiredSkills": "Python,Redis",
  "resumes": [
    {
      "type": "url",
      "file": {
        "name": "candidate.pdf",
        "path": "https://example.com/candidate.pdf",
        "extra": "candidate-001"
      }
    }
  ]
}
```

`file.extra` 优先于条目顶层 `extra`。服务在提交阶段同步下载并校验 URL；单项下载失败不会阻断同批其他任务。

批量提交响应：

```json
{
  "code": 0,
  "msg": "success",
  "total": 1,
  "submitted": 1,
  "failed": 0,
  "estimatedSeconds": 90,
  "tasks": [
    {
      "filename": "candidate.pdf",
      "extra": "candidate-001",
      "code": 0,
      "taskId": "uuid",
      "status": 0,
      "statusDesc": "待处理"
    }
  ]
}
```

### 3.3 异步仅解析与仅打标

`POST /api/resume/async/batch/parse` 请求与批量异步接口相同，但岗位上下文不参与解析。完成时 `data.result` 为：

```json
{
  "filename": "candidate.pdf",
  "extra": "candidate-001",
  "resumeParseFinishTime": "2026-08-04 10:00:00",
  "resume": {
    "candidate": {},
    "educations": [],
    "works": [],
    "projects": []
  }
}
```

将该对象放入下面请求的 `resumes` 数组即可仅打标：

```http
POST /api/resume/async/batch/tag
Content-Type: application/json
```

```json
{
  "jobTitle": "后端工程师",
  "resumes": [
    {
      "filename": "candidate.pdf",
      "extra": "candidate-001",
      "resumeParseFinishTime": "2026-08-04 10:00:00",
      "resume": {
        "candidate": {},
        "educations": [],
        "works": [],
        "projects": []
      }
    }
  ]
}
```

两个接口单次均限制 1~20 份。

### 3.4 混合批量

```http
POST /api/resume/async/batch/multiform
Content-Type: multipart/form-data
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `files` | File[] | 可重复提交的 PDF/DOCX/JPG/JPEG/PNG 上传字段 |
| `resumes` | string | `type=url` 条目数组的 JSON 字符串 |
| 岗位上下文字段 | string | 见 2.4 |

`files` 和 `resumes` 至少提供一个，合计最多 20 份。URL 条目或上传文件失败时按项返回错误。

### 3.5 轮询与任务列表

```http
GET /api/resume/async/result?taskId=<uuid>
```

终态成功：

```json
{
  "code": 0,
  "msg": "success",
  "data": {
    "taskId": "uuid",
    "status": 3,
    "statusDesc": "任务完成",
    "elapsedSeconds": 12.3,
    "estimatedSeconds": 90,
    "extra": "candidate-001",
    "result": {}
  }
}
```

任务不存在返回 HTTP 200、业务 `code=2001`。建议每 3~5 秒轮询，终态后停止。

```http
GET /api/tasks?status=3&include_result=false
```

`status` 可选；`include_result=true` 会返回完整简历。接口最多返回按创建时间倒序的 200 条记录，当前无认证，不应直接暴露到公网。

## 4. 同步接口

### 4.1 文件条目

同步批量的 `resumes` 元素支持：

```json
{"type":"url","file":{"name":"a.pdf","path":"https://example.com/a.pdf","extra":"id-1"}}
```

```json
{"type":"file","file":{"name":"a.docx","path":"/app/uploads/a.docx","extra":"id-2"}}
```

```json
{"type":"base64","file":{"name":"a.pdf","content":"<base64>","extra":"id-3"}}
```

`type=file` 会读取服务器可访问路径，属于高权限内部能力，生产必须限制调用者和根目录。

### 4.2 同步解析加打标

```http
POST /api/resume/sync/batch
Content-Type: application/json
```

```json
{
  "jobTitle": "后端工程师",
  "max_concurrency": 4,
  "resumes": [
    {"type":"url","file":{"name":"a.pdf","path":"https://example.com/a.pdf"}}
  ]
}
```

- 单次 1~50 份。
- `max_concurrency` 取值 1~30；未传时使用 `MAX_WORKERS`，运行时仍截断到 30。
- 每项独立返回 `code`、`data.status`、结果或错误。

### 4.3 同步仅解析

`POST /api/resume/sync/parse` 请求格式和限制与同步批量相同。成功项的 `data` 可直接作为 `/api/resume/sync/tag` 的输入元素。

### 4.4 同步仅打标

```http
POST /api/resume/sync/tag
Content-Type: application/json
```

请求使用 4.3 中的已解析 Resume 条目，单次 1~50 份，`max_concurrency` 为 1~30。

## 5. OpenAI 兼容接口

### 5.1 模型名

| model | 行为 |
|---|---|
| `DeepSeek-OCR` | 同步仅解析 PDF/DOCX/JPEG/PNG |
| `DeepSeek-OCR-JSON` | 解析加打标；同步与 `async_mode=true` 均支持 PDF/DOCX/JPG/JPEG/PNG，异步固定走纯图片视觉链 |
| `AIHR-Resume` | `/v1/models` 会列出，但当前 Chat 路由没有处理分支，会返回空 content；不应作为业务模型使用 |

这些是兼容层逻辑名称，不代表底层真实模型。真实模型由 `MODEL_NAME`、`ASYNC_MODEL_NAME`、`SYNC_MODEL_NAME` 和备用模型配置决定。

### 5.2 请求示例

```json
{
  "model": "DeepSeek-OCR-JSON",
  "stream": false,
  "async_mode": false,
  "messages": [
    {
      "role": "user",
      "content": [
        {"type":"url","file":{"name":"candidate.pdf","path":"https://example.com/candidate.pdf"}}
      ]
    }
  ]
}
```

非流式响应符合 Chat Completions 外壳，实际业务 JSON 位于 `choices[0].message.content` 字符串。`stream=true` 当前只发送一个包含完整 completion 的 SSE 事件，不是 token 级流式输出。`usage` 使用字符数近似，不是真实 tokenizer 统计。

## 6. 标签配置接口

### 6.1 更新正向维度

```http
PUT /api/tags/config/positive/skills
Authorization: Bearer <TAGS_ADMIN_TOKEN>
Content-Type: application/json
```

```json
{
  "displayName": "技能标签",
  "enabled": true,
  "allowedValues": ["Python", "Redis"]
}
```

结构保护要求维度集合及顺序与基线一致。允许值属于内容，可修改，但应同步维护标签 ID 映射和技能库，否则自动化一致性测试会失败。

### 6.2 更新负向维度和规则

负向维度只允许 `displayName`、`enabled`：

```json
{"enabled": false}
```

既有规则更新只能使用该规则已经存在的字段；新增字段返回 HTTP 400、`code=1005`。

### 6.3 更新扣分

```http
PUT /api/tags/config/severity
```

```json
{"low": 5, "medium": 10, "high": 20}
```

请求值必须是非负整数，服务保存为负扣分。

### 6.4 重置

`POST /api/tags/config/reset` 会删除运行时配置文件并立即回退到代码默认配置，不保留配置历史版本。

## 7. 算法调试接口

两个接口都接收：

```json
{
  "resume": {
    "candidate": {},
    "educations": [],
    "works": [],
    "projects": []
  },
  "jobInfo": {
    "jobTitle": "后端工程师"
  }
}
```

缺少或传入空 `resume` 时返回 HTTP 400。敏感标签调试接口只执行确定性规则，不等同于完整 `run_tagging` 结果。

## 8. 统一业务结果

完整结果顶层结构：

```json
{
  "taskId": "uuid",
  "mappingVersion": "ai-resume-parsertag:ID-mapping-tag:V1.0.1-20260806",
  "resumeParseFinishTime": "2026-08-04 10:00:00",
  "tagParseFinishTime": "2026-08-04 10:00:10",
  "candidate": {},
  "educations": [],
  "works": [],
  "projects": [],
  "positiveTags": {"tagsArray": []},
  "negativeTags": {
    "hitCount": 0,
    "deductionScore": 0,
    "tagsArray": []
  }
}
```

`positiveTags.tagsArray` 固定顺序为 `education`、`companyBg`、`workYears`、`skills`、`industry`。每个维度包含 `dimensionId`，每个 `value` 元素包含 `tagId/tag/source`；`source` 只允许 `rule`（纯规则）、`llm`（纯模型）和 `hybrid`（模型召回后由规则复核）。正负向标签使用相同契约。

`GET /api/tags/mapping` 返回当前 `mappingVersion`、全部维度记录和全部标签值记录；`GET /api/tags/config` 也返回同一个 `mappingVersion`。调用方应把业务数据上的版本和 ID 一并保存，版本不一致时重新获取映射，不能按数组位置绑定。

公开 Resume 的 `works[]` 仍只有 `company/position/description/startDate/endDate`。
`endDate` 的“目前/现在/在职/current/present/now”会归一为“至今”；原文未提供
结束日期时保持为空，不根据经历顺序推断。接口忽略额外的 `employmentType`
字段，实习/兼职由职位与描述关键词兼容识别。

`works[]` 保持原始字段结构，不增加任职类型字段。当前任职结束日期统一为 `至今`；实习和兼职仍根据职位及描述中的明确关键词识别。

## 9. 错误与 HTTP 语义

| 场景 | HTTP | 业务码/结构 |
|---|:---:|---|
| Pydantic 请求校验失败 | 422 | FastAPI `detail` |
| 多数文件/业务参数错误 | 200 | `code=1001/1002/1003/1004` |
| 任务不存在 | 200 | `code=2001` |
| 标签结构新增/删除 | 409 | `code=1003` |
| 标签结构保护失败 | 400 | `code=1005` |
| 管理 Token 错误 | 401 | FastAPI `detail` |
| OpenAI 文档解析失败 | 400 | `{"error":"..."}` |

当前错误语义并不统一，调用方必须同时检查 HTTP 状态码和业务 `code`。后续如统一为标准 HTTP 语义，需要通过版本化方式避免破坏现有集成。

## 10. 已知接口问题

1. `/v1/models` 暴露 `AIHR-Resume`，但 Chat 路由未实现对应分支。
2. `type=url` 尚未实施 SSRF 地址限制；`type=file` 尚未限制读取根目录。
3. 任务查询和完整结果当前无认证，生产环境有 PII 暴露风险。
