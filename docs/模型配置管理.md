# 模型配置管理

## 范围

页面 `/admin/models` 管理同步模型、异步模型及公共备用模型（有序、最多 8 个）。
同步/异步分别用同一模型完成解析与打标；第一版不提供打标覆盖、网关地址、密钥或推理参数编辑。
已有业务接口、Resume Schema、标签规则和映射版本不变。静态页面由 FastAPI 提供，使用 Tailwind CSS 4 与原生 JavaScript。前端开发时需 Node 构建 CSS，运行容器不需要 Node，不依赖任何外部 CDN。

## 部署

环境变量：

- `MODEL_ADMIN_TOKEN`：独立管理员 Bearer 凭证，缺省时所有模型管理 API 返回 503。
- `MODEL_CONFIG_FILE`：默认 `<项目目录>/runtime/model_config.json`；容器推荐 `/app/runtime/model_config.json`。
- 原有 `SYNC_MODEL_NAME`、`ASYNC_MODEL_NAME`、`FALLBACK_MODELS`：仅在持久化文件不存在时作为默认值。
- 网关 `MODEL_SERVICE_URL`、`API_KEY` 和推理参数仍在进程启动时读取，更改它们需要重新启动。

本地 Compose 已挂载 `./runtime:/app/runtime`。目录不加入 Git；镜像也不包含运行时配置。
K8s 应将可写 PVC 挂载到 `/app/runtime`，使用 Secret 注入管理凭证和网关密钥，并配置目录权限。
不要把运行时文件挂载成只读 ConfigMap，也不要由应用修改 Deployment 或调用 K8s API。

**仅支持一个 Pod、一个 Uvicorn worker。** 共享 PVC 不会同步不同进程的内存配置。
异步任务仍在内存中，Pod 重启会丢失任务；配置热更新不会重启 Pod。

启用管理前确认内网访问控制。跨机器使用 HTTPS；不要在 URL 中传递凭证。
静态页面壳可以匿名访问，但配置、模型列表、测试、应用、回退都必须鉴权。
页面不展示网关密钥；管理凭证只留在页面内存，刷新/退出后需重新输入。
第一版采用共享 Token，审计日志的操作者为 `shared-admin`，不代表已识别具体个人。

## 使用

1. 打开 `/admin/models`，输入 `MODEL_ADMIN_TOKEN`。
2. 登录后自动加载网关模型列表，并显示数量或失败原因；同步、异步使用单选下拉框，可搜索筛选。列表不完整时展开“手动填写 ID”。
3. 左侧导航分为运行概览、模型配置、模型测试。概览仅显示生效配置；模型配置页保存本页面草稿，切换模块不丢失。备用模型下拉多选，按勾选顺序加入，用上移/下移调整顺序，可移除或留空。
   配置页顶部为三个紧凑配置卡片，下方用小卡片展示全部匹配模型，支持搜索；卡片标记生效/草稿用途，不推断模型能力，选择操作集中在顶部。桌面默认状态尽量一屏展示，模型多时仅卡片区域滚动；展开高级选项或小屏时允许必要滚动。侧边栏支持桌面收起为图标栏（悬停显示菜单名称），再次点击可展开；移动端仍使用抽屉导航。可选模型区域可收起/展开，保留搜索条件和草稿。操作反馈使用右上角浮动提醒，2 秒自动消失且不占页面布局；登录认证错误仍保留在登录表单内。
4. 模型测试页使用紧凑工具栏与结果表格，可以选择当前生效配置或未应用草稿；结果仅显示状态、耗时和用途，失败原因按需展开。常见桌面视口内一屏展示，模型较多时仅表格区域滚动，表头保持可见。两种对象的结果分开记录，修改草稿后草稿测试结果失效。测试针对所有去重后的主备模型，不使用回退、不应用配置；文本/图片使用随机四位数字且无 PII。
5. 核对应用确认框中的差异，点击应用；可在测试未通过时经明确确认继续应用。
6. 用真实简历回归业务质量，出现问题时回退上一版。

测试使用当前业务调用的参数兼容逻辑，每个模型每次 HTTP 尝试超时 45 秒、输出上限 1024、SDK 重试 0。
同一进程仅允许一个测试请求在执行。样例通过不保证上下文容量、完整简历效果或业务延迟。
解析存在视觉输入，因此主模型及备用模型都应支持图片。新模型需已在网关配置并授权。
不支持现有推理参数的新模型可能仍需代码适配；仅改模型名不等于支持所有供应商协议。

## 一致性与恢复

- HTTP 请求进入时固定不可变配置快照，整个同步批次及该请求创建的异步任务共用它。
- 线程池通过现有 `wrap_for_executor` 继承上下文；排队任务不会在执行时重新选配置。
- 生效配置优先于环境默认值，页面显示来源、版本及时间。
- 应用时校验 `expectedVersion`；过时请求返回 409，需刷新后再修改。
- 当前配置和上一版写入同一 JSON，临时文件 flush/fsync 后原子替换；替换成功后更新内存。
- 持久化失败时返回 503，内存配置保持不变。原子替换不是备份，底层存储故障仍依赖运维恢复。
- 重建容器后加载持久化配置。文件损坏时启动失败，不静默退回环境默认值。
- 回退恢复上一版内容，但生成递增的新版本；仅影响后续任务，不重跑历史数据。
- 日志记录应用前后配置，以及 LLM 使用的配置版本、主模型与备用链；真实调用仍有模型日志。
- 手动改文件不支持自动监视生效，必须使用管理 API；离线修复文件后需要重启。

## 前端开发与验证

```bash
cd web
npm ci --ignore-scripts
npm run build
npx playwright install chromium
npm test
```

`styles.css` 使用 Tailwind，扫描 `model-config.html` 与 `assets/model-config.js`。修改样式类后重新构建，将 `assets/model-config.css` 一并提交。依赖版本固定在 `package-lock.json`；不要手改生成 CSS。
浏览器回归使用本地拦截的 API，不修改真实配置、不调用模型。可用 `PLAYWRIGHT_CHROMIUM_EXECUTABLE` 指定已有 Chromium。

Docker 只复制 HTML 及 `web/assets/`，不安装前端依赖；生成 CSS 随镜像离线交付。`/admin/model-assets/{filename}` 仅开放固定 CSS/JS 文件，不暴露源码、构建配置或依赖目录。新增资源路由不进入公开业务 OpenAPI。

## 管理 API

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/api/admin/models/config` | 当前配置、上一版 |
| PUT | `/api/admin/models/config` | 校验并应用 |
| POST | `/api/admin/models/rollback` | 回退上一版 |
| GET | `/api/admin/models/catalog` | 网关模型列表 |
| POST | `/api/admin/models/test` | 文本/视觉样例测试 |

详见 `/docs` 及 `docs/openapi.json`。管理操作也属于生产变更，建议按团队流程提前说明。
